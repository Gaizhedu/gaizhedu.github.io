# 知识远征

全屏像素风答题小游戏，纯 HTML、CSS、JavaScript，无第三方依赖。

## 运行

在项目目录运行 `npm start`，打开 http://localhost:4173 。也可双击 `start-game.cmd`。停止服务器时按 Ctrl+C。

游戏需要通过 HTTP 读取题库，请不要直接双击 HTML。浏览器记录按访问地址分别保存，例如 localhost:4173 与 localhost:4174 不共享记录。

## 移动与答题

- 点击「开始游戏」后，底部显示后退、跳跃、前进三个箭头。
- 前进或后退点按一次移动 48 个世界单位；按住超过 300 毫秒可连续移动，松开后完成当前一步。遇到怪物或宝箱立即停止并显示题目，长按状态会清除。
- 后退不能越过起点，也不能退到已探索最远位置之前 180 个世界单位以外。
- 玩家右走使用第 7 行，左走使用第 3 行，均只使用该行前 3 帧；精灵行号从 1 开始。
- 上箭头跳跃。键盘向左/向右（可长按）、向上跳跃、空格前进、数字 1–4 作答。
- 怪物题目为紫色，宝箱题目为金色；每次遭遇只有一道四选一题，选完不显示答案。
- 作答后立即在题目区域显示正误，所选选项答对为绿色、答错为红色。「查看详情」默认折叠，展开可读正确答案和解析。点击「继续」后自动迈一步；最后一题点击「查看结果」结算。
- 打开记录抽屉、窗口失焦或切到其他标签页时会停止连续移动。

## 怪物与宝箱数量

在每份题库 JSON 的 `questionBank` 中配置：

```json
"totalQuestionRatio": 0.3,
"encounterRatios": {
  "monster": { "ratio": 0.7, "difficulties": ["easy"] },
  "chest": { "ratio": 0.2, "difficulties": ["easy", "normal"] },
  "headChest": { "ratio": 0.1, "difficulties": ["hard"] }
}
```

`totalQuestionRatio` 是本局总题数占整个题库有效去重题数的比例，必须大于 0 且不超过 1。本局总题量为两者相乘后向上取整；为保留最终怪物和路上宝箱，最少安排 2 题。

三个 `ratio` 分别是怪物、路上宝箱、可选顶头宝箱占本局总题量的比例，三项必须相加等于 1。怪物及路上宝箱比例须大于 0；顶头宝箱可设为 0 关闭，也可以高于另外两项。先取各类理论题量的整数部分，再将剩余名额按小数部分从大到小分配；小数相同时按怪物、路上宝箱、头顶宝箱顺序分配。若怪物或路上宝箱分到 0 题，从其他类别调一个名额，保持总数不变。

例如 80 题 × 0.3 = 24 题，按 0.7 / 0.2 / 0.1 分配，理论数量为 16.8 / 4.8 / 2.4，最终安排 17 只怪物、5 个路上宝箱、2 个头顶宝箱，总计 24 题。

`difficulties` 指定该类遭遇允许抽取的难度，可选 `easy`、`normal`、`hard`，支持组合，例如 `["easy", "normal"]`。要让头顶宝箱只出困难题，将 `headChest` 改为 `{ "ratio": 0.1, "difficulties": ["hard"] }`。当前题库总占比均为 0.3；分类比例和难度以各 JSON 配置为准，专业英语提供 Easy、Plus、Pro 三种版本。题目未填 `difficulty` 时按 `easy` 处理。纯数字分类配置表示不限难度。

兼容未填写 `totalQuestionRatio` 的旧题库：分类比例仍直接乘以整库题数，相加不超过 1，头顶宝箱比例须小于另外两项。旧题库缺少 `encounterRatios` 时采用 0.3 / 0.2 / 0.1，且不限难度。使用新规则时应同时填写总占比和相加为 1 的分类比例。

指定难度的题目不足时会减少对应遭遇，不重复抽题、不混入未允许的难度。先保证一个最终怪物和一个路上宝箱，再补充怪物、路上宝箱和头顶宝箱；完全没有符合条件的头顶宝箱题时不生成头顶宝箱。无法安排两道不同的怪物和路上宝箱题时，题库列表会显示配置错误。

最后一次遭遇固定为头顶 diamond 钻石的怪物，所有题目不重复。指定难度不足造成的缺额不自动转给其他类别，实际总题数可能少于预算。

宝箱从本局开始就放在固定位置，进入视野时提前可见，不会等前一道题结束才突然出现。顶头箱可以直接路过；落到玩家身后 160～220 个世界单位时渐隐，超过 220 时清除。未开启的可选箱不计错题、不进入分数分母；计分只使用实际作答题数。

结算分别显示怪物及路上宝箱完成题数、头顶宝箱开启数/本局总数，同时显示答对题数和分数。
## 游玩次数与本地记录

- 顶部「游玩次数」显示累计完成的游戏次数，中途刷新或离开不计入成绩。
- 点击次数打开右侧抽屉，只显示最近 20 次的正确题数和分数，最新记录排在最上面。
- 分数为 `round(答对题数 / 本局总题数 × 100)`，怪物与宝箱题等权计算。例如答对 3/4 题为 75 分。
- 累计次数独立于最近 20 条记录保留，使用 localStorage 保存，刷新后仍然存在。
- 存储键为 `knowledge-quest-history-v1`。浏览器禁止存储时本次仍可游玩，抽屉中会提示无法持久保存。

- `ground/single_block.png`：64 单位方块拼接的平坦地面。

- `enemies/evil_3x.png`：第 3 行，6 帧。
- `ui/left.png`、`ui/upper.png`、`ui/right.png`：移动按钮。
- `items/fish_can_1.png` 至 `fish_can_6.png`：路上宝箱，随机起始款式后循环使用六款。`items/diamond.png`：最后怪物标记。

## 添加题库

将 JSON 放进 `question` 文件夹并刷新。自带服务器自动发现题库，每局只使用当前选中的题库，相同题干与选项会在该题库内去重。

支持 `questionBank.questions`、顶层 `questions` 或题目数组。必需字段为 `questionDetail`、`optionA`–`optionD`、`correctOption`（A–D）。`explanation` 可选，`type` 为 `single_choice` 或省略。

若使用其他静态服务器，在 `config.json` 的 `questionFiles` 列出题库文件名，或提供 `question/index.json` 文件名数组。

## 验证

运行 `npm test`，覆盖单步/长按控制、后退边界、碰撞、额外宝箱抽题、不重复题目、计分、历史记录去重及存储恢复。

## 攻击、跳跃与顶头宝箱

- 每题显示后等待 0.5 秒才可回答。答题后播放约 0.72 秒的头顶剑图标挥动；怪物被击退、倾倒并淡出。动画结束后可点击「继续」或「查看结果」，反馈和详解不会自动消失。
- 全程使用平坦地面，角色、怪物和路上宝箱处于同一地面高度。上箭头仍可跳跃、顶开悬空宝箱，落地后可再次起跳。
- 按题库配置的比例安排使用 `items/chest_head.png` 的可选悬空宝箱。移动到下方，按上箭头从底部顶中才会弹起并出题，单纯走近不会触发。
- 普通箱与顶头箱共用不重复抽题和计分。题库不足时减少怪物数量；仅两题时保留一个路上宝箱和最终怪物。
- `items/sword.png` 为每次答题后的攻击图标，`world.js` 管理地形、跳跃、顶头碰撞和动画时长。
## 切换题库

点击左上角 castle 城堡图标打开左侧题库抽屉。名称优先读取 JSON 内部的 `questionBank.title`（也支持 `name` 及顶层 `title`/`name`），不使用文件名；缺少名称显示“未命名题库”。列表同时显示有效题数和当前选中状态。

选择另一题库后整页重新加载并自动开始新一局，未完成的旧局不计入历史。选择保存在浏览器中，URL 的 `bank` 参数可保留当前题库；抽屉打开时暂停游戏，关闭后恢复。结算窗口也提供切换入口。每个可选题库至少需要两道不同的有效单选题。
## 题目文字格式

题干、四个选项、结算回顾和解析均支持受限 HTML：`<strong>关键词</strong>` 或 `<b>关键词</b>` 加粗，`<em>`/`<i>` 斜体，`<code>` 行内代码，`<br>` 或换行符换行。例如 JSON 中可写 `"questionDetail": "请解释 <strong>Sprint Goal</strong> 的含义。"`。

无需修改现有带 strong 标签的题库。只识别以上不带属性的标签，其余内容作为普通文字显示，不执行脚本或事件；未闭合的格式标签会自动补齐，避免影响选项等界面。


素材采用运行时白名单，未使用的旧角色、旧路上宝箱及所有大小写 PSD 文件均由 .gitignore 忽略。

## 自动继续设置
右上角 spring 图标打开游戏设置。「自动跳过答对的题目」默认勾选，并在本地保存选择。开启后，答对会在画面中央显示 items/right.png，约 0.72 秒后自动继续；最后一题自动结算。答错仍保留红色反馈、详解与手动继续。关闭选项后，答对也需要手动继续。打开设置时游戏暂停。
